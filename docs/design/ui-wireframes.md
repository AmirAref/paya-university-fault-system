# طرح اولیه رابط کاربری (UI Wireframes) – سامانه مدیریت و گزارش خرابی دانشگاهی

**تهیه‌کننده:** رضا آدوسی  
**بازبین:** ارشیا همتی‌زاده  
**آخرین به‌روزرسانی:** ۱۴۰۵/۰۸/۱۸  
**وضعیت سند:** نسخه اولیه (Draft) – آماده بازبینی

---

## ۱. مقدمه

هدف این سند، ارائه طرح اولیه رابط کاربری سامانه مدیریت و گزارش خرابی دانشگاهی (پایا) است. در این طراحی، صفحات اصلی سامانه، اطلاعات قابل مشاهده، ورودی‌های موردنیاز کاربر و پاسخ سیستم به عملیات مختلف مشخص می‌شوند.

تمرکز این مرحله بر روشن بودن مسیر انجام کارها و تعامل کاربران با سامانه است، نه طراحی گرافیکی نهایی. جزئیات ظاهری مانند رنگ‌بندی، فونت و تصاویر در مراحل بعدی توسعه تعیین خواهند شد.

## ۲. نقش‌های کاربری

رابط کاربری سامانه با توجه به نقش و سطح دسترسی کاربران، بخش‌های متفاوتی را نمایش می‌دهد.

| نقش کاربر | وظایف اصلی در سامانه |
|---|---|
| دانشجو | ثبت خرابی، مشاهده و پیگیری گزارش‌ها |
| استاد | ثبت خرابی، مشاهده و پیگیری گزارش‌ها |
| کارمند تأسیسات | بررسی گزارش‌ها، تعیین اولویت و ارجاع به تعمیرکار |
| تعمیرکار | مشاهده وظایف ارجاع‌شده، به‌روزرسانی وضعیت و ثبت نتیجه تعمیر |
| مدیر | مشاهده وضعیت کلی گزارش‌ها و اطلاعات مدیریتی |

## ۳. صفحات اصلی سامانه

### ۳.۱. صفحه ورود (Login)

**کاربران:** تمام نقش‌ها

هدف این صفحه احراز هویت کاربران و ورود به بخش متناسب با سطح دسترسی آن‌هاست.

**طرح اولیه:**

```text
+------------------------------------------+
|            سامانه پایا                   |
|    سامانه مدیریت و گزارش خرابی دانشگاه   |
|                                          |
|       نام کاربری: [________________]     |
|                                          |
|       رمز عبور:   [________________]     |
|                                          |
|              [ ورود ]                   |
|                                          |
|  پیام خطا:                               |
|  اطلاعات ورود نامعتبر است.               |
+------------------------------------------+
```

**ورودی‌ها:**
- نام کاربری
- رمز عبور

**عملیات و پاسخ سیستم:**
- با وارد کردن اطلاعات معتبر، کاربر وارد داشبورد متناسب با نقش خود می‌شود.
- در صورت اشتباه بودن اطلاعات، پیام خطای مناسب نمایش داده می‌شود.
- در صورت خالی بودن فیلدهای ضروری، از ارسال فرم جلوگیری می‌شود.

### ۳.۲. داشبورد دانشجو و استاد

**کاربران:** دانشجو، استاد

این صفحه نقطه شروع فعالیت گزارش‌دهندگان پس از ورود به سامانه است.

**طرح اولیه:**

```text
+------------------------------------------------+
| سامانه پایا                 [نام کاربر] [خروج] |
+------------------------------------------------+
| منوی اصلی                                      |
|                                                |
| [داشبورد]  [ثبت گزارش خرابی]  [گزارش‌های من]  |
+------------------------------------------------+
| داشبورد                                        |
|                                                |
| تعداد گزارش‌های ثبت‌شده:  5                    |
| گزارش‌های در حال بررسی:   2                    |
| گزارش‌های در حال تعمیر:   1                    |
| گزارش‌های تکمیل‌شده:      2                    |
|                                                |
| آخرین گزارش‌ها:                                |
| +------+-------------+-------------+---------+ |
| | کد   | عنوان       | تاریخ       | وضعیت  | |
| +------+-------------+-------------+---------+ |
| | 101  | خرابی پروژکتور| ۱۴۰۵/۰۸/۱۰| در حال بررسی | |
| | 102  | مشکل روشنایی | ۱۴۰۵/۰۸/۱۱| در حال تعمیر | |
| +------+-------------+-------------+---------+ |
|                                                |
|           [ ثبت گزارش جدید ]                   |
+------------------------------------------------+
```

**اطلاعات قابل مشاهده:**
- تعداد گزارش‌های ثبت‌شده توسط کاربر
- تعداد گزارش‌ها بر اساس وضعیت
- فهرست آخرین گزارش‌ها
- شناسه، عنوان، تاریخ و وضعیت هر گزارش

**عملیات:**
- ورود به صفحه ثبت گزارش جدید
- مشاهده فهرست گزارش‌های قبلی
- مشاهده جزئیات و وضعیت هر گزارش

### ۳.۳. صفحه ثبت گزارش خرابی (Create Fault Report)

**کاربران:** دانشجو، استاد

در این صفحه کاربر اطلاعات مربوط به خرابی را وارد و گزارش خود را ثبت می‌کند.

**طرح اولیه:**

```text
+------------------------------------------------+
| ثبت گزارش خرابی                                |
+------------------------------------------------+
| عنوان خرابی:                                   |
| [________________________________________]     |
|                                                |
| توضیحات:                                       |
| [________________________________________]     |
| [________________________________________]     |
|                                                |
| محل وقوع خرابی:                                |
| [________________________________________]     |
|                                                |
| نوع خرابی:                                     |
| [ انتخاب نوع خرابی                  ▼ ]        |
|                                                |
| اطلاعات تکمیلی / تصویر (اختیاری):              |
| [ انتخاب فایل ]                                |
|                                                |
|             [ ثبت گزارش ]                      |
|             [ انصراف ]                          |
+------------------------------------------------+
```

**ورودی‌ها:**
- عنوان خرابی
- توضیحات خرابی
- محل وقوع خرابی
- نوع خرابی
- فایل یا تصویر مرتبط (اختیاری)

**عملیات و پاسخ سیستم:**
- پس از تکمیل اطلاعات ضروری، کاربر با انتخاب «ثبت گزارش» درخواست خود را ارسال می‌کند.
- سیستم اطلاعات را اعتبارسنجی و گزارش را ذخیره می‌کند.
- در صورت ثبت موفق، پیام تأیید همراه با شناسه گزارش نمایش داده می‌شود.
- در صورت ناقص بودن اطلاعات ضروری، پیام خطای مرتبط نمایش داده می‌شود.

**نمونه پیام موفقیت:**

```text
گزارش خرابی با موفقیت ثبت شد.
شناسه گزارش: 103
وضعیت: ثبت‌شده
```

### ۳.۴. صفحه فهرست و جزئیات گزارش‌ها

**کاربران:** دانشجو، استاد، کارمند تأسیسات، مدیر

این صفحه برای مشاهده گزارش‌ها و بررسی وضعیت آن‌ها استفاده می‌شود. اطلاعات و عملیات قابل دسترس با توجه به نقش کاربر متفاوت خواهد بود.

**طرح اولیه فهرست گزارش‌ها:**

```text
+------------------------------------------------+
| گزارش‌های خرابی                                |
+------------------------------------------------+
| جست‌وجو: [____________________]                |
| وضعیت:   [همه وضعیت‌ها             ▼]          |
|                                                |
| +------+-------------+-------------+----------+|
| | کد   | عنوان       | محل         | وضعیت   ||
| +------+-------------+-------------+----------+|
| | 101  | خرابی پروژکتور| کلاس ۱۰۱  | ثبت‌شده  ||
| | 102  | مشکل روشنایی | راهرو      | در حال تعمیر||
| | 103  | خرابی کولر   | کلاس ۲۰۲  | در حال بررسی||
| +------+-------------+-------------+----------+|
|                                                |
|       [ مشاهده جزئیات گزارش ]                  |
+------------------------------------------------+
```

**اطلاعات قابل مشاهده در صفحه جزئیات:**
- شناسه گزارش
- عنوان و توضیحات خرابی
- محل وقوع
- تاریخ ثبت
- وضعیت فعلی
- اولویت (در صورت تعیین)
- مسئول رسیدگی (در صورت ارجاع)
- سوابق تغییر وضعیت و اقدامات انجام‌شده

**عملیات:**
- جست‌وجو و فیلتر گزارش‌ها
- مشاهده جزئیات گزارش
- مشاهده تاریخچه تغییرات، متناسب با سطح دسترسی کاربر

### ۳.۵. داشبورد کارمند تأسیسات

**کاربر:** کارمند تأسیسات

این صفحه برای بررسی گزارش‌های ثبت‌شده، تعیین اولویت و ارجاع آن‌ها به تعمیرکار طراحی می‌شود.

**طرح اولیه:**

```text
+------------------------------------------------+
| داشبورد کارمند تأسیسات       [نام کاربر] [خروج]|
+------------------------------------------------+
| [گزارش‌های جدید] [در حال بررسی] [ارجاع‌شده]    |
+------------------------------------------------+
| گزارش‌های نیازمند بررسی                        |
|                                                |
| +------+-------------+------------+-----------+|
| | کد   | عنوان       | محل        | اولویت   ||
| +------+-------------+------------+-----------+|
| | 101  | خرابی پروژکتور| کلاس ۱۰۱ | تعیین‌نشده||
| | 103  | خرابی کولر  | کلاس ۲۰۲  | تعیین‌نشده||
| +------+-------------+------------+-----------+|
|                                                |
|             [ بررسی گزارش ]                    |
+------------------------------------------------+
```

**عملیات در صفحه بررسی گزارش:**
- مشاهده اطلاعات گزارش
- تعیین اولویت گزارش
- ثبت توضیحات یا درخواست اطلاعات تکمیلی
- انتخاب تعمیرکار و ارجاع گزارش
- مشاهده وضعیت گزارش‌های قبلی

**پاسخ سیستم:**
- پس از تعیین اولویت، اطلاعات گزارش به‌روزرسانی می‌شود.
- پس از ارجاع موفق، گزارش به فهرست وظایف تعمیرکار اضافه می‌شود.
- در صورت نامعتبر بودن ارجاع یا انتخاب نکردن تعمیرکار، پیام خطا نمایش داده می‌شود.

تعمیرکار از این صفحه برای مشاهده وظایف ارجاع‌شده و ثبت پیشرفت کار استفاده می‌کند.

**پاسخ سیستم:**
- پس از ثبت موفق، وضعیت گزارش به‌روزرسانی می‌شود.
- نتیجه تعمیر در سوابق گزارش ذخیره می‌شود.
- در صورت ناموفق بودن عملیات، پیام خطا نمایش داده می‌شود.

### ۳.۷. داشبورد مدیر

**کاربر:** مدیر

این صفحه برای مشاهده وضعیت کلی سامانه و نظارت بر گزارش‌های خرابی طراحی می‌شود.

**طرح اولیه:**

**اطلاعات قابل مشاهده:**
- تعداد کل گزارش‌ها
- تعداد گزارش‌ها بر اساس وضعیت
- آمار کلی عملکرد سامانه
- آخرین گزارش‌های ثبت‌شده

**عملیات:**
- مشاهده گزارش‌های کلی
- بررسی وضعیت گزارش‌ها
- دسترسی به اطلاعات مدیریتی متناسب با سطح دسترسی

## ۴. سناریوی کامل تعامل کاربر با سامانه

برای بررسی ارتباط صفحات و روشن شدن جریان اطلاعات، سناریوی زیر در نظر گرفته شده است.

**سناریو: ثبت و پیگیری خرابی پروژکتور توسط دانشجو**

۱. دانشجو وارد صفحه ورود می‌شود و اطلاعات حساب کاربری خود را وارد می‌کند.

۲. پس از ورود موفق، داشبورد دانشجو نمایش داده می‌شود.

۳. دانشجو گزینه «ثبت گزارش خرابی» را انتخاب می‌کند.

۴. عنوان، توضیحات و محل وقوع خرابی را وارد کرده و گزارش را ثبت می‌کند.

۵. سیستم اطلاعات را اعتبارسنجی می‌کند. در صورت معتبر بودن، گزارش ذخیره شده و یک شناسه یکتا به آن اختصاص داده می‌شود.

۶. کارمند تأسیسات گزارش جدید را در فهرست گزارش‌های نیازمند بررسی مشاهده می‌کند.

۷. کارمند تأسیسات گزارش را بررسی کرده، اولویت آن را تعیین و به یک تعمیرکار ارجاع می‌دهد.

۸. تعمیرکار گزارش را در فهرست وظایف خود مشاهده کرده و پس از شروع کار، وضعیت آن را به‌روزرسانی می‌کند.

۹. پس از انجام تعمیر، تعمیرکار نتیجه اقدامات را ثبت می‌کند.

۱۰. دانشجو می‌تواند با مراجعه به فهرست گزارش‌های خود، وضعیت و نتیجه تعمیر را مشاهده کند.

## ۵. حالت‌های خطا و رفتار مورد انتظار سیستم

| حالت خطا | رفتار مورد انتظار |
|---|---|
| وارد کردن نام کاربری یا رمز عبور اشتباه | نمایش پیام خطای ورود و باقی ماندن در صفحه ورود |
| خالی بودن فیلدهای ضروری هنگام ثبت گزارش | جلوگیری از ثبت و مشخص کردن فیلدهای ناقص |
| بروز خطا هنگام ذخیره گزارش | نمایش پیام عدم موفقیت و امکان تلاش مجدد |
| تلاش کاربر برای مشاهده گزارش غیرمجاز | جلوگیری از دسترسی و نمایش پیام مناسب |
| ارجاع گزارش بدون انتخاب تعمیرکار | جلوگیری از ارجاع و درخواست انتخاب تعمیرکار |
| ثبت نتیجه تعمیر بدون توضیحات ضروری | نمایش خطا و درخواست تکمیل اطلاعات |

## ۶. نکات و تصمیم‌های طراحی

- صفحات بر اساس نقش کاربر طراحی شده‌اند و گزینه‌های قابل مشاهده به سطح دسترسی او وابسته هستند.
- شناسه گزارش پس از ثبت موفق توسط سیستم اختصاص داده می‌شود.
- وضعیت گزارش باید در صفحات مختلف به‌صورت هماهنگ نمایش داده شود.
- اطلاعاتی مانند اولویت، تعمیرکار مسئول و نتیجه تعمیر فقط پس از ثبت توسط کاربران مجاز نمایش داده می‌شوند.
- طراحی فعلی مفهومی است و جزئیات گرافیکی و فنی در مراحل بعدی تکمیل خواهند شد.
- در طراحی نهایی باید از نمایش یا ویرایش اطلاعات توسط کاربران فاقد مجوز جلوگیری شود.

## ۷. نکات و کارهای باقی‌مانده

- بازبینی صفحات توسط اعضای تیم
- تطبیق فیلدهای فرم ثبت خرابی با مستند نیازمندی‌ها و داستان‌های کاربر
- نهایی‌سازی وضعیت‌های ممکن برای گزارش خرابی
- بررسی جزئیات سطح دسترسی هر نقش
- تکمیل طراحی صفحات بر اساس بازخورد تیم و استاد

## ۸. وضعیت سند

نسخه اولیه (Draft) – آماده بازبینی
